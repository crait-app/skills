Quick Start (3 Steps)

Get up and running in minutes

1

Install

使用 Claude Code CLI 安装技能

claude-code skill install python-code-analyzer
2

Config

无需配置！开箱即用。可选：创建 .python-analyzer.yml 自定义规则。
3

First Trigger

只需询问：'分析我的 Python 代码' 或提及具体文件

@analyze app.py

Overview

为什么选择这个 Skill？

每个 Python 开发者都面临同样的挑战：

  • 隐藏的 Bug：通过测试但在生产环境中崩溃的微妙问题
  • 性能陷阱：能运行但比应有速度慢 10 倍的代码
  • 技术债务：不断累积的复杂度，直到重构变得不可能

这个技能通过在编码时提供即时、可操作的反馈来解决这些问题。

核心功能

🔍 静态分析

  • 检测常见 bug：未使用的变量、未定义的名称、导入错误
  • 在反模式进入生产环境之前识别它们
  • 突出显示潜在的运行时错误

⚡ 性能优化

  • 发现 N+1 查询、低效循环和内存泄漏
  • 建议更快的算法和数据结构
  • 提供前后性能估算

📐 复杂度指标

  • 计算圈复杂度和认知复杂度
  • 识别过于复杂而难以维护的函数
  • 推荐具体的重构策略

🎨 样式与最佳实践

  • 强制执行 PEP 8 和团队特定约定
  • 建议更 Pythonic 的编码方式
  • 解释为什么某些模式更好

高级功能

自定义规则配置

在项目根目录创建 .python-analyzer.yml：

 1rules:
 2  max_line_length: 120
 3  max_function_length: 50
 4  max_complexity: 10
 5
 6ignore_patterns:
 7  - "*/migrations/*"
 8  - "*/tests/fixtures/*"
 9
10custom_rules:
11  - no_print_statements  # 标记生产代码中的 print()
12  - require_type_hints   # 强制类型注解

常见问题

Q: 这会减慢我的开发速度吗？ A: 不会 - 大多数文件的分析在 1 秒内完成。在调试上节省的时间远远超过分析时间。

Q: 我可以使用公司的编码标准吗？ A: 可以 - 通过 .python-analyzer.yml 配置文件完全可自定义。

Q: 它支持类型提示和异步代码吗？ A: 支持 - 完全支持 Python 3.8+ 功能，包括类型注解、async/await 和模式匹配。

Q: 与 pylint/flake8 相比如何？ A: 这个技能利用这些工具，但添加了 AI 驱动的解释和理解特定代码库的上下文感知建议。
